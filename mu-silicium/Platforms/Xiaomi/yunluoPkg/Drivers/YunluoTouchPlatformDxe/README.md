# YunluoTouchPlatformDxe

This is the first UEFI-side platform adaptation unit for the NT36523 Windows
route. It publishes the already-established yunluo resource facts through a
private UEFI protocol:

- GPIO base `0x10005000`, region `0x1000`
- SPI0 MMIO `0x1100a000`, region `0x100`
- GPIO30/31/32/33 = CLK/CS/MOSI/MISO
- touch GPIO8
- SPI mode 0

It intentionally performs no MMIO or GPIO writes, no reset, no firmware upload,
no IRQ installation and no touch report generation. This makes it safe to add
to an isolated UEFI build before a Windows consumer exists.

The Windows-only `yunluo-6g-winboot` DSC/FDF includes this module. An isolated
Ubuntu2404 ext4 board snapshot has passed a complete AARCH64 DEBUG_CLANGPDB build,
host contract regression and FV inclusion checks. The shared Mu package sources
and tracked repository states were not changed by that build.

The protocol GUID is declared in this driver's private DEC and generated by
EDK II AutoGen; the firmware file GUID is distinct. GetInfo zeroes reserved and
padding bytes and rejects invalid arguments/revisions.

Receipt: `evidence/uefi-touch-build-20261030-1750-d/validated-result.json` at the
workspace root. The v8 boot image is a resource-only diagnostic candidate, not
a finished touchscreen implementation.

This protocol is boot-services-only. It does not create a Windows-visible ACPI
node or runtime transport, and Windows cannot call it after ExitBootServices.
Platform initialization and an actual Windows consumer remain future work.
Do not add it to the shipping/common firmware without a separate review.
